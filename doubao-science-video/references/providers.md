# 豆包模型执行与恢复

以下为工作流经验，模型目录、接口与收费会变化。执行时以当前官方文档、CLI帮助和账户资源为准。不要把示例音色视为永久可用。

## 生图/生视频的启用条件

默认纯程序动画，不调用生图或生视频模型。只有用户明确要求相应模态时，才执行以下图片/视频资源选择与生成。允许一个模态不自动允许另一个；不得以“先做参考图”“低成本试一段”绕过授权。TTS是独立流程，优先复用已有配音。

## 视频：方舟 / Seedance

先执行 [预算与重试控制](budget.md)。优先已有素材和本地示意，普通关键动态优先评估较低成本模型；不能因低价模型不可用而自动切换昂贵模型或补买资源包。科学正确性不达标时优先改用准确示意动画。执行时核对当前价格、分辨率、输入媒体计费和最低用量规则，不把历史促销价当现价。

降低分辨率可减少部分模型的用量，但须检验可读性；最终导出720p不等于素材原生720p。Draft样片与正式视频可能分别计费，不能默认草稿免费；离线折扣也需确认当前模型支持。不为追求较低 token 单价而无必要地输入参考视频，输入时长及最低计费量可能增加总价。

有 arkcli 时，使用它的认证、资源解析、参数核验和生成 Skill。明确的 Endpoint 优先于当前 profile 默认值，Endpoint 必须从用户或当前账户查询取得，不能复用其他项目的 ID。

典型路由（先看本机 --help）：

```bash
arkcli resources list --modality video
arkcli resources resolve "$VIDEO_ENDPOINT"
arkcli models get "$VIDEO_MODEL" --transform supported_params
# 仅传当前资源支持的生成参数
arkcli +gen --model "$VIDEO_RESOURCE" --modality video --save-to ./clips "镜头描述"
arkcli gen get "$TASK_ID"
```

模型名可查 supported_params；Endpoint 按当前 CLI 的资源解析规则处理，不能凭命名推断能力。异步生成需以 succeeded 和本地可读媒体双重确认。签名下载链接会过期，交付持久本地文件。调用失败时保留脱敏错误摘要，不把返回体全量写入共享仓库。

## 语音：豆包语音服务

方舟通用 API Key 不代表具备豆包语音权限。先核对语音产品开通状态、认证方式、资源 ID、音色权限及配额；401 后停止重复使用同一错误凭据。不要仅为试接口擅自创建或替换账号密钥。

优先使用当前正式可用的高质量 TTS。亲和女生可试听 Vivi 等当前中文女声音色，比较咬字、自然度、术语发音及段间稳定性；名字和 speaker ID 从实时音色目录取得，不凭记忆硬编码。

优先经官方 API 生成，并保留真实时间戳（若支持）。如果缺少独立语音鉴权，且用户允许控制台工作流，可使用官方语音体验中心生成和导出。不要伪称 API 已接通。需要登录验证时让用户完成敏感操作。

控制台绕行要点：
1. 测试一小段音色，固定音色与语速后逐段生成。
2. 按段落 ID 命名，每次下载后校验文件大小、时长、可解码性与内容，避免历史结果错配。
3. 出现批量下载权限或 Blob 导出工具限制时，在授权范围内走原生浏览器下载，不循环重试不支持的下载 API。
4. 新出现的服务开通/下载协议，展示具体条款影响并按用户授权处理；已批准的同一操作不重复确认。免费额度、后付费或资源包选择从当前页面核实。
5. 下载仅表示文件取得，音频与口播一致仍需试听核对。

尽量保持一致的采样率与响度；不要因控制台有试听音频就假设正式服务已开通，两者分别回读。
